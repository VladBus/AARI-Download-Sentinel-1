# AARI-Download-Sentinel-1

Автоматизация поиска и загрузки исходных продуктов Sentinel-1 для рабочей территории Северного морского пути (СМП).

## Текущий этап разработки

Реализовано:

- конфигурация проекта через локальный файл .env;
- построение поисковой области СМП с буфером 150 км;
- обработка пересечения 180-го меридиана;
- проверка доступа к CDSE S3 без скачивания данных;
- поиск Sentinel-1 EW GRDM с HH+HV через CDSE OData;
- раздельные запросы для частей полигона по обе стороны 180-го меридиана;
- обработка пагинации OData и устранение повторов;
- сохранение результатов поиска в локальный JSON;
- проверка точного S3-префикса отдельного SAFE-продукта;
- полный просмотр состава SAFE-продукта и расчёт суммарного объёма;
- загрузка одного SAFE-продукта из CDSE S3 с сохранением исходной структуры;
- пропуск уже загруженных файлов при повторном запуске, если их размер совпадает с размером объекта в S3;
- проверка размера каждого загруженного объекта;
- атомарная публикация скачанных файлов через временные `.part`-файлы;
- сохранение `download_manifest.json` с состоянием каждого объекта и возможностью аудита прерванной загрузки;
- организация продукта в отдельной папке по дате, времени, режиму, платформе и Datatake ID;
- создание быстрых ссылок на поляризационные TIFF и копии quick-look;
- проверка каталога хранения с тестом записи, чтения и удаления;
- переключение корневого каталога через .env или параметр CLI;
- модульные тесты конфигурации, геометрии, OData, инвентаризации S3, хранения и загрузки.

## Требования

- Windows 10/11 x64;
- Python 3.14 (разработка ведётся на Python 3.14.3);
- виртуальное окружение .venv;
- учётная запись Copernicus Data Space Ecosystem;
- действующие S3 Access Key и Secret Key.

Параметр `CDSE_S3_CHECK_PREFIX` по умолчанию установлен в `Sentinel-1/SAR/EW_GRDM_1S/`, то есть в каталог EW GRDM, соответствующий целевому типу продукта.

## Первоначальная настройка

В корне проекта:

~~~powershell
py -3.14 -m venv .venv
.\.venv\Scripts\activate.bat
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
~~~

Создайте локальный файл конфигурации:

~~~powershell
Copy-Item .env.example .env
~~~

Если терминал открыт в cmd.exe, используйте:

~~~bat
copy .env.example .env
~~~

В `.env` заполните `CDSE_ACCESS_KEY` и `CDSE_SECRET_KEY`. Никогда не добавляйте реальные ключи в Git.

Поместите рабочий файл `SMP.geojson` сюда:

~~~text
data\geometry\SMP.geojson
~~~

Исходная геометрия, поисковые результаты, логи и скачанные данные исключены из Git.

## Проверка CDSE S3

~~~powershell
python main.py --check-s3
~~~

Команда выполняет один запрос ListObjectsV2 к бакету `eodata` с префиксом `Sentinel-1/SAR/EW_GRDM_1S/` и `MaxKeys=1`. Она проверяет доступ к листингу каталога, не скачивая снимки.

## Поиск Sentinel-1

Укажите даты в формате `YYYY-MM-DD`. Конечная дата включается в поиск.

~~~powershell
python main.py --search-s1 --start-date 2026-11-10 --end-date 2026-11-12
~~~

По умолчанию поиск выполняется для:

- коллекции SENTINEL-1;
- типа продукта `EW_GRDM_1S`;
- поляризационного кода `DH` (HH+HV);
- геометрии из `data\geometry\SMP_search_area_150km.geojson`;
- максимума 500 продуктов.

OData запрашивает каждую часть поисковой геометрии отдельно. Результаты объединяются по идентификатору продукта. Обрабатываются все страницы ответа до достижения лимита или окончания результатов.

Пример с другим лимитом:

~~~powershell
python main.py --search-s1 --start-date 2026-11-10 --end-date 2026-11-12 --max-products 200
~~~

Полный результат записывается в `data\search_results\` в формате JSON. В терминале выводятся количество найденных продуктов, параметры запроса и первые 20 результатов с именами и S3Path.

## Проверка точного S3-префикса продукта

После поиска OData можно проверить первые пять объектов выбранного продукта:

~~~powershell
python main.py --check-s3-product --search-report "data\search_results\sentinel1_EW_GRDM_1S_DH_2026-11-24_2026-11-25.json" --product-index 0
~~~

Команда проверяет наличие объектов под точным SAFE-префиксом. Она не скачивает снимок. Параметр `--product-index` — нулевой индекс записи в массиве `products` JSON-отчёта.

## Инвентаризация SAFE перед загрузкой

Перед скачиванием рекомендуется получить полный состав продукта и общий объём:

~~~powershell
python main.py --plan-s3-download --search-report "data\search_results\sentinel1_EW_GRDM_1S_DH_2026-11-24_2026-11-25.json" --product-index 0
~~~

Команда проходит все страницы S3-листинга, считает количество объектов и суммарный размер. В выводе отображаются общий объём в байтах, MiB и GiB, а также примеры объектов. Данные на диск не скачиваются.

## Проверка каталога хранения

Перед первой загрузкой или после смены корневого каталога проверьте выбранное хранилище:

~~~powershell
python main.py --check-storage
~~~

Команда использует `S1_DOWNLOAD_DIR` из локального `.env`. Для проверки другого каталога:

~~~powershell
python main.py --check-storage --download-dir "D:\\Sentinel-1"
~~~

Проверка создаёт каталог при необходимости, записывает и читает временный файл, затем удаляет его. Существующие файлы не изменяются. Команда не обращается к CDSE и не скачивает данные. Перед каждой фактической загрузкой та же проверка выполняется автоматически.

Корневой каталог можно переключать без изменения кода:

- локально: `S1_DOWNLOAD_DIR=data/downloads`;
- другой локальный диск: `S1_DOWNLOAD_DIR=D:\\Sentinel-1`;
- сетевой ресурс Windows: `S1_DOWNLOAD_DIR=\\\\10.31.34.60\\Tiris\\Sentinel-1`.

Для текущего этапа оставьте локальный путь. Сетевой путь будет установлен после подтверждения выделенного каталога и проверки прав доступа.

## Загрузка одного SAFE-продукта

Для загрузки выбранного продукта:

~~~powershell
python main.py --download-product --search-report "data\search_results\sentinel1_EW_GRDM_1S_DH_2026-11-24_2026-11-25.json" --product-index 0
~~~

По умолчанию продукт сохраняется в:

~~~text
data\downloads\YYYY-MM-DD_HHMMSS-HHMMSS_EW_S1C_DATATAKE\
~~~

Можно указать другой локальный каталог:

~~~powershell
python main.py --download-product --search-report "data\search_results\sentinel1_EW_GRDM_1S_DH_2026-11-24_2026-11-25.json" --product-index 0 --download-dir "D:\Sentinel-1"
~~~

Особенности загрузки:

- загружаются все объекты, перечисленные внутри точного SAFE-префикса;
- сохраняется относительная структура каталогов продукта;
- для крупных объектов используется multipart-загрузка boto3;
- каждый объект сначала скачивается во временный файл с расширением `.part`;
- после завершения передачи размер временного файла сверяется с размером объекта в S3;
- только после успешной проверки временный файл атомарно переименовывается в окончательное имя;
- при ошибке временный файл удаляется, а незавершённое состояние фиксируется в манифесте;
- при повторном запуске файлы с совпадающим размером пропускаются, а отсутствующие или имеющие другой размер скачиваются заново;
- после обработки каждого объекта обновляется `download_manifest.json` в корне папки продукта.

Манифест содержит имя продукта, S3-префикс, общий объём и состояние каждого объекта (`pending`, `downloaded`, `skipped_existing` или `failed`). Значение `verification: size_match` означает проверку размера, а не криптографическую проверку содержимого. Полная проверка контрольных сумм пока не реализована.

**Массовую загрузку пока не запускайте.** Сначала проверьте новую структуру на одном тестовом продукте и убедитесь, что исходный SAFE, поляризационные TIFF и quick-look расположены правильно.

## Организация загруженного продукта

Каждый продукт сохраняется в отдельной папке с датой, временем съёмки, режимом,
платформой и Datatake ID. Например:

~~~text
data\downloads\
└── 2026-11-24_030553-030653_EW_S1C_014EEB\
    ├── HH.tiff
    ├── HV.tiff
    ├── quick-look.png
    ├── product.json
    ├── download_manifest.json
    └── source.SAFE\
        ├── manifest.safe
        ├── annotation\
        ├── measurement\
        ├── preview\
        └── support\
~~~

HH.tiff и HV.tiff — удобные ссылки на исходные measurement TIFF:
сначала создаются hard links без дублирования данных; если файловая система
не поддерживает hard links, используется копирование. Исходный SAFE остаётся
полным и неизменным внутри source.SAFE, поскольку manifest.safe и SNAP
ожидают штатную структуру продукта. quick-look.png копируется из preview/.
Файл product.json содержит идентификаторы и сведения об организации продукта.

Для однополяризационных продуктов создаётся только соответствующий TIFF.

## Безопасность

- `.env` содержит ключи доступа и исключён из Git.
- `data/` и `logs/` исключены из Git.
- Не публикуйте Secret Key, Access Key ID и рабочие геоданные без разрешения.
- Секреты не выводятся в логах и отчётах.

## План дальнейшей разработки

1. Проверка новой структуры на контрольном SAFE-продукте — выполнена.
2. Атомарная загрузка и манифест состояния продукта — реализованы; требуется локальное тестирование.
3. Предварительная проверка каталога хранения и переключение корневого пути через .env или CLI — реализовано; требуется локальное тестирование.
4. Дополнительная проверка целостности по контрольным суммам, если CDSE предоставляет совместимые значения.
5. Подготовка сетевого каталога и проверка прав доступа после его выделения.
6. Перенос SNAP/GDAL-обработки из SAR Ice Studio в headless Python pipeline.
7. Сквозное тестирование и запуск через Windows Task Scheduler.
8. Перенос проверенного конвейера на Linux и настройка cron.
