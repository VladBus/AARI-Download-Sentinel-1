# AARI-Download-Sentinel-1

Автоматизация поиска и загрузки исходных продуктов Sentinel-1 для рабочей территории Северного морского пути (СМП).

## Текущий этап разработки

Реализовано:

- конфигурация проекта через локальный файл .env;
- построение поисковой области СМП с буфером 150 км;
- обработка пересечения 180-го меридиана;
- проверка доступа к CDSE S3 без скачивания данных;
- поиск Sentinel-1 EW GRDM с HH+HV через CDSE OData;
- раздельные запросы для частей полигона по обе стороны 180-го меридиана;
- обработка пагинации OData и устранение повторов;
- сохранение результатов поиска в локальный JSON;
- проверка точного S3-префикса отдельного SAFE-продукта;
- полный просмотр состава SAFE-продукта и расчёт суммарного объёма;
- загрузка одного SAFE-продукта из CDSE S3 с сохранением структуры каталогов;
- пропуск уже загруженных файлов при повторном запуске, если их размер совпадает с размером объекта в S3;
- проверка размера каждого загруженного объекта;
- модульные тесты конфигурации, геометрии, OData, инвентаризации S3 и загрузки.

## Требования

- Windows 10/11 x64;
- Python 3.14 (разработка ведётся на Python 3.14.3);
- виртуальное окружение .venv;
- учётная запись Copernicus Data Space Ecosystem;
- действующие S3 Access Key и Secret Key.

Параметр `CDSE_S3_CHECK_PREFIX` по умолчанию установлен в `Sentinel-1/SAR/EW_GRDM_1S/`, то есть в каталог EW GRDM, соответствующий целевому типу продукта.

## Первоначальная настройка

В корне проекта:

~~~powershell
py -3.14 -m venv .venv
.\.venv\Scripts\activate.bat
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
~~~

Создайте локальный файл конфигурации:

~~~powershell
Copy-Item .env.example .env
~~~

Если терминал открыт в cmd.exe, используйте:

~~~bat
copy .env.example .env
~~~

В `.env` заполните `CDSE_ACCESS_KEY` и `CDSE_SECRET_KEY`. Никогда не добавляйте реальные ключи в Git.

Поместите рабочий файл `SMP.geojson` сюда:

~~~text
data\geometry\SMP.geojson
~~~

Исходная геометрия, поисковые результаты, логи и скачанные данные исключены из Git.

## Проверка CDSE S3

~~~powershell
python main.py --check-s3
~~~

Команда выполняет один запрос ListObjectsV2 к бакету `eodata` с префиксом `Sentinel-1/SAR/EW_GRDM_1S/` и `MaxKeys=1`. Она проверяет доступ к листингу каталога, не скачивая снимки.

## Поиск Sentinel-1

Укажите даты в формате `YYYY-MM-DD`. Конечная дата включается в поиск.

~~~powershell
python main.py --search-s1 --start-date 2026-11-10 --end-date 2026-11-12
~~~

По умолчанию поиск выполняется для:

- коллекции SENTINEL-1;
- типа продукта `EW_GRDM_1S`;
- поляризационного кода `DH` (HH+HV);
- геометрии из `data\geometry\SMP_search_area_150km.geojson`;
- максимума 500 продуктов.

OData запрашивает каждую часть поисковой геометрии отдельно. Результаты объединяются по идентификатору продукта. Обрабатываются все страницы ответа до достижения лимита или окончания результатов.

Пример с другим лимитом:

~~~powershell
python main.py --search-s1 --start-date 2026-11-10 --end-date 2026-11-12 --max-products 200
~~~

Полный результат записывается в `data\search_results\` в формате JSON. В терминале выводятся количество найденных продуктов, параметры запроса и первые 20 результатов с именами и S3Path.

## Проверка точного S3-префикса продукта

После поиска OData можно проверить первые пять объектов выбранного продукта:

~~~powershell
python main.py --check-s3-product --search-report "data\search_results\sentinel1_EW_GRDM_1S_DH_2026-11-24_2026-11-25.json" --product-index 0
~~~

Команда проверяет наличие объектов под точным SAFE-префиксом. Она не скачивает снимок. Параметр `--product-index` — нулевой индекс записи в массиве `products` JSON-отчёта.

## Инвентаризация SAFE перед загрузкой

Перед скачиванием рекомендуется получить полный состав продукта и общий объём:

~~~powershell
python main.py --plan-s3-download --search-report "data\search_results\sentinel1_EW_GRDM_1S_DH_2026-11-24_2026-11-25.json" --product-index 0
~~~

Команда проходит все страницы S3-листинга, считает количество объектов и суммарный размер. В выводе отображаются общий объём в байтах, MiB и GiB, а также примеры объектов. Данные на диск не скачиваются.

## Загрузка одного SAFE-продукта

Для загрузки выбранного продукта:

~~~powershell
python main.py --download-product --search-report "data\search_results\sentinel1_EW_GRDM_1S_DH_2026-11-24_2026-11-25.json" --product-index 0
~~~

По умолчанию продукт сохраняется в:

~~~text
data\downloads\<ИМЯ_ПРОДУКТА>.SAFE\
~~~

Можно указать другой локальный каталог:

~~~powershell
python main.py --download-product --search-report "data\search_results\sentinel1_EW_GRDM_1S_DH_2026-11-24_2026-11-25.json" --product-index 0 --download-dir "D:\Sentinel-1"
~~~

Особенности загрузки:

- загружаются все объекты, перечисленные внутри точного SAFE-префикса;
- сохраняется относительная структура каталогов продукта;
- для крупных объектов используется multipart-загрузка boto3;
- после скачивания размер каждого файла сверяется с размером объекта в S3;
- при повторном запуске файлы с совпадающим размером пропускаются;
- если загрузка прервалась посреди отдельного файла, этот файл при следующем запуске будет загружен заново; ранее завершённые файлы повторно не скачиваются.

Проверка размера не является полной криптографической проверкой содержимого. Отдельная проверка контрольных сумм будет добавлена при развитии механизма контроля целостности.

**Не запускайте массовую загрузку всех найденных продуктов на этом этапе.** Сначала следует проверить инвентаризацию и загрузить один тестовый SAFE-продукт.

## Безопасность

- `.env` содержит ключи доступа и исключён из Git.
- `data/` и `logs/` исключены из Git.
- Не публикуйте Secret Key, Access Key ID и рабочие геоданные без разрешения.
- Секреты не выводятся в логах и отчётах.

## План дальнейшей разработки

1. Проверка инвентаризации и тестовая загрузка одного SAFE-продукта.
2. Улучшение контроля целостности и обработки прерванных загрузок.
3. Защита от повторного скачивания, журналирование и ежедневный запуск через Windows Task Scheduler.
4. Постобработка SAR-продуктов (отдельный этап).
